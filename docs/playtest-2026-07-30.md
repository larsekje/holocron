### A. Rules reference: skills, maneuvers, range bands
Notes: "List of skills and symbol spends", "How many range bands for a
maneuver", "What maneuvers can be used for".

The Symbol spends modal (`components/reference/SymbolSpendsModal.tsx`, opened
with **R** or the header triumph icon) already has tabs. Add tabs:

- **Skills** — every skill with its characteristic and a one-line "use it
  for" (General / Combat / Knowledge groups). Skill data exists in the
  Spotlight index (`type: 'skill'`, see `data/spotlightIndex.ts`); prefer it
  over a hand-written list.
- **Maneuvers & range** — what a maneuver can be spent on (aim, assist, guarded
  stance, interact with environment, manage gear, mount/dismount, move, drop
  prone/stand, preparation) and the movement cost between range bands
  (engaged↔short 1 maneuver, short→medium 1, medium→long 2, long→extreme 2;
  max 2 maneuvers/turn, the second costs 2 strain).
- Consider renaming the modal/tooltip to "Rules reference" since it no longer
  covers only spends.
- Also link the "Maneuver" rows in `components/turnbar/TurnActionsHint.tsx` to
  the new tab (click opens the reference on it).

Verify: screenshot each tab.

### B. Disorient: apply the status and roll with it
Note: "Disorient status".

`StatusFactories.disoriented` exists and the Apply Effects modal (**E**) can
add it, but nothing *uses* it: a disoriented participant's rolls don't get the
Setback, and hitting with a Disorient-quality weapon doesn't offer it.

- When an attack / skill-check snapshot is built for a participant with an
  active Disoriented N (see `state/effectStore.ts`), add N Setback dice with
  source label `Disoriented N` (builders in `utils/diceSnapshots.ts`).
- In `components/dice/SpendPanel.tsx`, weapons with the Disorient N quality get
  a spend option (cost ⌒⌒, combat mode, target) that applies
  `StatusFactories.disoriented(id, target, N, N)` to the target. Mirror how
  existing active-quality spends (e.g. Knockdown/Stun) apply effects.
- Rules: Disorient N — the target is disoriented for N rounds; a disoriented
  character adds ■ to all checks.

Verify: fixture, apply Disoriented 2 to Pirates via E, open a Pirates attack →
two Setback dice labelled "Disoriented 2".

### C. Improvised weapons
Note: "IMprovised weapons".

PCs in the tracker have no weapon list (Rodas Olo in the fixture), so an
attack can't be rolled for them at all; and anyone can grab a bottle or chair.
Add an always-available **Improvised weapon** entry to every participant's
weapon list in the Active sheet (`components/statblock/WeaponListOld.tsx`,
reached via `ParticipantSheetView`) that opens the normal attack roller
(`buildAttackSnapshot`).

Rules (Edge of the Empire CRB, improvised weapons): Melee skill, Engaged,
Damage = Brawn + 1, Crit 5, Inferior. (Inferior is already handled by
`applyWeaponQualityModifiers`.) If you're unsure of the exact stats, flag it in
the PR rather than inventing a size table.

Verify: fixture, make Rodas active, his sheet shows "Improvised weapon";
clicking opens a Melee attack at Engaged.

### D. Opposed checks
Note: "Opposed checks".

The roller has an `opposed` mode (`DiceRollMode`, `OpposedPanel`) but only
mock snapshots use it — nothing in the app opens one. Build the flow:

- An entry point from the Active sheet's skill list: "Opposed…" on a skill,
  then pick the opponent and their opposing skill.
- Pool: the actor's skill dice vs. Difficulty dice from the opponent's
  opposing skill/characteristic (the higher of the two = number of purple
  dice, the lower = how many become red Challenge). Common pairs: Deception vs
  Discipline, Stealth vs Perception, Coercion vs Discipline, Charm vs Cool,
  Negotiation vs Negotiation, Brawl vs Brawl.
- A builder in `utils/diceSnapshots.ts` next to `buildSkillCheckSnapshot`
  (note: B also edits this file — rebase onto whichever lands first).

Verify: fixture, Sall: Coercion vs Rodas's Discipline → pool shows Sall's
dice vs purple/red from Rodas.

### E. Encounter roster: companions, sidelined NPCs, editable slots, picking on the shared screen
Notes: "Companion NPC", "Track npcs that is not in current encounter",
"Manipulate npc slots (remove when ded)", "Select active slot on shared
screen".

What the playtest shows: Brunt, Veem Saalo and Sliprigg are Rodas's crew, but
`Participant` only knows `isPC`, so they were adversaries: listed under
"Adversaries", given NPC slots, shown red on the shared screen. Sliprigg was
deleted at the start of encounter 1 and re-added (as "Slicer", fresh stats)
for encounter 3 — there's no way to keep someone tracked but out of the fight.
And deleting the killed Pirate Crew mid-encounter left its slot behind
(slots are only disabled for *dead* participants, `utils/initiativeSlots.ts`).

1. **Companions**: an optional `side: 'PC' | 'NPC'` (default from `isPC`) on
   `Participant`, toggled from the target row's ⋮ menu. Companions list under
   the PCs (e.g. "Party"), take PC-team slots when initiative is rolled
   (`components/turnbar/InitiativeModal.tsx`), count for PC slot
   eligibility/disable logic, and show as PC team on the shared screen
   (`sync/snapshot.ts`).
2. **Sidelined**: an `offstage?: boolean` that keeps wounds/strain/pouch but
   removes the participant from initiative, slot counting, the shared screen
   and the live lists; a collapsed "Off-stage" section brings them back
   ("Bring in" adds a slot when an encounter is running).
3. **Slots**: removing a participant mid-encounter removes one trailing slot
   of their team (adjusting `currentTurnIndex`); clicking a slot in
   `InitiativeOrder` offers remove / add PC slot / add NPC slot.
4. **Shared screen picking**: with companions on the PC team, the player view's
   "Who's acting?" (`player/PlayerTurnControls.tsx`) lists them; also let
   players tap a name in `PlayerRoster` during an open PC slot.

This is the largest brief; split into one commit per numbered item.
